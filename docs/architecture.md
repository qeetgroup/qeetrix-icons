# Architecture

`@qeetrix/icons` 2.0 turns one pinned Lucide release into React 19 components. Outline SVGs are
synced from Lucide ([lucide.md](lucide.md)), filled SVGs are derived from them
([filled.md](filled.md)), and both are validated ([validation.md](validation.md)) and generated
into components, a root barrel, and a manifest ([generation.md](generation.md)). The public
contract is [api.md](api.md): one component per icon concept, with a `variant` prop typed to its
drawings. The technology is Bun, strict TypeScript, React 19, and ESM, with Biome and Vitest.

## Pipeline

```text
Lucide release (GitHub tag)
        -> bun run sync:lucide     icons/outline/, config/lucide.json, config/categories.ts
        -> bun run derive:filled   icons/filled/, for the icons in config/filled.ts
        -> bun run check:icons     validate every source SVG and the metadata
        -> bun run generate        components, root barrel, manifest module, icon-manifest.json
        -> bun run build           dist/, the only published directory
        -> playground              human visual review (repository only)
        -> Qeetrix UI / Qeet products
```

`sync:lucide` runs `derive:filled` and `generate` itself. `generate` repeats the validation and
aborts on any error without writing. `check:filled` and `check:generated` prove that the committed
filled drawings and generated files match their sources; CI and the release gate run them with
`check:icons`.

Generation converts validated sources to JSX without changing geometry, precision, or drawing
order; there is no SVG optimization step. The sync and the filled derivation write SVG sources,
not components, so SVG remains the source of truth for every drawing.

## What exists

| Surface | Responsibility |
|:--|:--|
| `icons/outline/` | Lucide's outline SVGs, written by `sync:lucide`, one folder per primary category |
| `icons/filled/` | Filled SVGs, written by `derive:filled`, in the outline's category folder |
| [config/lucide.json](../config/lucide.json) | Pinned Lucide version, its categories, and per-icon categories, tags, and aliases |
| [config/categories.ts](../config/categories.ts) | Lucide's 42 categories in id order; generated by `sync:lucide` |
| [config/filled.ts](../config/filled.ts) | Which icons get a filled drawing, with optional per-element roles |
| [config/icon-metadata.ts](../config/icon-metadata.ts) | Per-icon metadata: Lucide's data plus the RTL `mirror` list ([rtl.md](rtl.md)) |
| [config/icon-system.ts](../config/icon-system.ts) | Internal design contract: architecture and the `design` values ([design.md](design.md)) |
| [src/types/icon.ts](../src/types/icon.ts) | Stable variant and directionality vocabulary |
| [src/types/icon-props.ts](../src/types/icon-props.ts) | Public `IconProps` |
| [src/types/icon-manifest.ts](../src/types/icon-manifest.ts) | Public manifest schema types |
| [src/runtime/resolve-icon-props.ts](../src/runtime/resolve-icon-props.ts) | Shared size and accessibility defaults for generated components |
| `src/generated/` | Generated barrel, manifest module, and one component module per concept |
| [src/index.ts](../src/index.ts) | Hand-written root: re-exports the generated barrel and the public types |
| [src/manifest.ts](../src/manifest.ts) | Hand-written `@qeetrix/icons/manifest` entry |
| `icon-manifest.json` | Generated manifest for repository tooling; not published |
| `scripts/sync/` | The `sync:lucide` CLI |
| `scripts/check/` | Source validation and the `check:icons` and `check:generated` CLIs |
| `scripts/build/` | The `generate` and `derive:filled` (and `check:filled`) CLIs |
| `scripts/lib/` | Lucide reading, filled derivation, diagnostics, SVG-to-React conversion, rendering, planning, and safe output |
| `playground/` | Internal Vite + React visual QA tool; reads generated output, never published |
| `docs/` | Design, naming, accessibility, RTL, pipeline, and release contracts |
| [tests/repository.test.ts](../tests/repository.test.ts) | Config consistency, sources against the manifest, and the package boundary |
| [tests/validation.test.ts](../tests/validation.test.ts) | Synthetic in-memory cases and isolated temporary scanner fixtures |
| [tests/lucide.test.ts](../tests/lucide.test.ts) | Lucide SVG normalization, release reading, and the committed Lucide data |
| [tests/filled.test.ts](../tests/filled.test.ts) | Filled derivation: roles, inference, cuts, gaps, precision, and determinism |
| [tests/generation.test.ts](../tests/generation.test.ts) | Conversion, determinism, Biome/TypeScript output checks, and output safety |
| [tests/runtime.test.ts](../tests/runtime.test.ts) | Rendering, props, refs, and accessibility of generated components |
| [tests/package.test.ts](../tests/package.test.ts) | Packed-tarball resolution, type, boundary, contents, and tree-shaking checks |
| [tests/playground.test.ts](../tests/playground.test.ts) | Playground data model, URL state, boundary, and a fixture build |
| `dist/` | Compiler output; the only build directory and published payload directory |

The main TypeScript config includes `config/`, `scripts/`, `src/`, tests, and the Vitest
configuration under strict checking. The build config keeps `rootDir` and `include` limited to
`src/`. Internal config may import public types, but public source and declarations must not
depend on unpublished config, so design values, Lucide data, and the taxonomy stay out of the
consumer API and build output. The runtime therefore repeats the default size of 24, and tests keep
it equal to the config value.

## Ownership map

| Kind | Location | Author |
|:--|:--|:--|
| SYNCED | `icons/outline/`, `config/lucide.json`, `config/categories.ts` | `sync:lucide`, from Lucide; never edited by hand |
| DERIVED | `icons/filled/` | `derive:filled`, from the outlines and `config/filled.ts`; never edited by hand |
| GENERATED | `src/generated/`, `icon-manifest.json` | `generate`; never edited by hand |
| AUTHORED CONFIG | `config/filled.ts`, `config/icon-metadata.ts`, `config/icon-system.ts` | People |
| RUNTIME | `src/runtime/` | People: behavior shared by generated components, nothing else |
| PUBLIC ENTRIES | `src/index.ts`, `src/manifest.ts`, `src/types/` | People |
| TOOLING | `scripts/` | People; never published |

The source layout is `icons/<variant>/<category>/<name>.svg`. Generated components are flat,
`src/generated/icons/<id>.tsx`, one per concept and keyed by public id, so neither category,
variant, nor source layout leaks into package paths.

## Determinism and dependencies

Each tool is the only author of what it writes. Output contains no timestamps, absolute paths, or
machine-dependent values. Generated name ordering uses explicit codepoint comparison, and category
ordering follows the order in `config/categories.ts`. `check:filled` and `check:generated` detect
drift without relying on Git.

React 19 is the only peer dependency, and there are no runtime dependencies; Lucide's artwork is
copied in by the sync, not installed. The runtime helper imports React only for types. Development
dependencies, each with one purpose:

- `@xmldom/xmldom`: the XML parser behind validation, the sync, and the derivation
  ([validation.md](validation.md#parser-decision)).
- `canvaskit-wasm`, pinned to `0.42.0`: Skia path operations for the filled derivation
  ([filled.md](filled.md)).
- `react`, `react-dom`, and their types: typecheck generated output and render it in tests.
- `vite`, already installed through Vitest: runs and builds the playground.

Generation uses no transformer, optimizer, or formatter dependency: it prints Biome-formatted code
directly. The playground has no React plugin, UI kit, router, or icon library; it uses React,
native controls, and local CSS tokens. It enumerates generated modules with Vite's
`import.meta.glob`, inside `playground/` only. The package still has no registry and no
`<Icon name>` API, and nothing in the playground is published: `files` ships only `dist/`, and the
playground builds to `playground/dist/`.

Validation and generation tests use synthetic geometry only, never production artwork. See
[releases.md](releases.md) before release work: the package version is still 1.x, and 2.0 must not
ship as a patch.
