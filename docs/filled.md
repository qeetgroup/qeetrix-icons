# Filled drawings

Lucide is outline-only. The filled variants are a Qeetrix addition: each one is derived from its
Lucide outline by path operations, not drawn by hand, and then reviewed by eye. 794 icons have
one; the list is [config/filled.ts](../config/filled.ts). Each listed icon gets a filled drawing in
both shapes: this page describes the round one, and [sharp.md](sharp.md#sharp-filled-drawings) how
the sharp one reuses it.

```bash
bun run derive:filled   # write icons/round-filled/ from config/filled.ts and the round outlines
bun run check:filled    # fail if any filled drawing is missing, stale, or unlisted; writes nothing
```

`derive:filled` ([derive-filled.ts](../scripts/build/derive-filled.ts)) writes each listed icon to
`icons/round-filled/<category>/<name>.svg`, in the same category folder as its outline. It owns
`icons/round-filled/` entirely: a drawing whose name is no longer listed is deleted, and so is an
empty category folder. If any listed icon fails to derive, or names an icon with no outline, it
reports every failure and writes nothing. CI and the release gate run `check:filled` alongside
`check:icons` and `check:generated`, so a changed outline, recipe, or derivation rule cannot leave
the committed drawings behind. After `derive:filled`, run `bun run derive:sharp`, which derives the
sharp filled drawings from the same list, and then `bun run generate` to update the components.

The engine is [CanvasKit](https://skia.org/docs/user/modules/canvaskit/), Skia's path operations
compiled to WebAssembly, as the development dependency `canvaskit-wasm`, pinned to `0.42.0`. It
runs only at derivation time. The output is a static SVG source like any other, so nothing ships
at runtime and generation treats filled sources exactly as it treats outlines.

## Output

Every filled drawing is a single `<path>` painted with `currentColor`, with `fill-rule="evenodd"`
when Skia's result uses it, and a comment naming its outline:

```xml
<!-- Derived from icons/round-outline/account/star.svg by `bun run derive:filled`. Do not edit this file directly. -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="currentColor">
  <path d="M10.629 1.851Q11.05 1 12 1Q12.95 1 13.371 1.851L15.682 6.531…Z" fill-rule="evenodd"/>
</svg>
```

Bodies are filled to the outline's painted extent: the shape's interior plus its stroke, expanded
with the outline's caps and joins (round here, square and mitered for the sharp style). A filled
icon therefore covers the same footprint as its outline, and the two can swap in place.
Coordinates have at most three decimals. Never edit a filled SVG; change the recipe or the
derivation and run `derive:filled` again.

## Roles

Each geometry element of the outline (`path`, `circle`, `rect`, and so on, in drawing order) plays
one role in the filled drawing:

| Role | Becomes |
|:--|:--|
| `fill` | A solid body: the shape's interior plus its stroke |
| `stroke` | Stays a line, joined to the silhouette |
| `cut` | A detail inside a body, knocked out as a negative line of stroke width. A dot is cut whole |
| `gap` | Stays a line, with 1 unit of clearance cut on each side where it crosses a body |
| `front` | A solid body in front of the others, with 1 unit of clearance cut around it |
| `hole` | Knocked out entirely, interior and stroke |
| `skip` | Left out |

A dot is a shape the outline paints solid (Lucide draws small dots with `fill="currentColor"`, such
as the hole in `tag`) or one so small that its stroke covers its interior. A `cut` removes a dot
whole; any larger shape is cut as a ring of stroke width around its interior.

## Inference

Most recipes are empty and every role is inferred. `deriveFilled` in
[scripts/lib/filled.ts](../scripts/lib/filled.ts) considers elements from the largest solid area
(interior plus stroke) to the smallest, and gives each the first role that applies:

1. **`cut`**: its stroke lies inside the bodies found so far. A sliver of up to 2% of the stroke may
   fall outside, because a round cap can graze a body's edge.
2. **`stroke`**: it is an open path whose open ends all lie on bodies, and it either encloses area
   (an attached curve, such as a lock shackle or bag handle, whose chord should not be filled) or
   runs mostly between bodies (a connector, such as the lines of `share-2`).
3. **`fill`**: it encloses area.
4. **`gap`**: it is a line crossing a body.
5. **`stroke`**: anything else.

Bodies are the `fill` and `front` elements found so far. `front`, `hole`, and `skip` are never
inferred; only a recipe sets them.

## Composition

The drawing is built in three passes:

1. **Bodies and lines.** Every `fill` body and every `stroke` and `gap` line is added.
2. **Gaps and fronts.** For each `gap` or `front` element, a clearance (the element stroked at the
   stroke width plus 1 unit on each side) is subtracted. A `front` element also has its interior
   subtracted. Then the line (`gap`) or solid body (`front`) is added back on top.
3. **Cuts and holes.** Each `cut` and `hole` is subtracted last, so a detail inside a front body,
   such as the check on `copy-check`, stays cut.

### Precision

Strokes are expanded as if at 64× scale (the `precision` option of CanvasKit's stroker). Skia's
stroker fits curves to a pixel-sized tolerance, and icon geometry lives on a 24-unit grid that
renders far larger; stroked at 1×, the small circles come out as rounded squares.

Skia's boolean operations can return an empty or partial path when edges coincide exactly, such as
a round cap ending on another stroke's edge. Every boolean result is therefore checked against its
operands' areas: a union must be at least the larger operand and at most their sum, a difference
between the left operand minus the right and the left operand, and an intersection no larger than
the smaller operand. Curve flattening makes measured areas approximate, so each bound allows 0.1
square units plus 1% of the larger operand. An implausible result is retried with the second
operand nudged by about a ten-thousandth of a unit, which is invisible. If every attempt fails,
derivation fails for that icon and reports the areas.

Boolean results are nested, non-crossing contours, which the even-odd rule fills exactly. Skia's
`makeAsWinding()` is not used, because it can orient a hole like its outer contour.

## Recipes

[config/filled.ts](../config/filled.ts) maps icon names to recipes, grouped by source category. An
empty recipe infers every role; `roles` overrides the role of an element by its 0-based index in
the outline source.

```ts
export const filledRecipes: Readonly<Record<string, FilledRecipe>> = {
  star: {},
  // Element 0, the clip <rect>, is a solid body in front of the board, with a gap around it.
  clipboard: { roles: { 0: "front" } },
  // Element 0, the handle, stays attached; inference would make it a gap line through the lens.
  search: { roles: { 0: "stroke" } },
};
```

An index outside the outline's elements is an error. Because roles are keyed by index, an
override is tied to the outline as Lucide drew it: when an upgrade redraws an icon, re-check its
recipe ([lucide.md](lucide.md#upgrading-lucide)). Sharpening keeps element order and count, so the
same indices hold for the sharp outline, and the sharp filled drawing plays every element in the
role the round one gave it.

## What is listed

Every listed icon was reviewed visually against its outline, and an icon is listed only when its
solid form is clean and consistent with the rest. Deliberately excluded:

- Open-line icons: bare arrows and chevrons, corners, refresh and rotate arcs, Wi-Fi and RSS arcs.
  An arrow or chevron inside a circle or square is listed (it becomes a cut), and so are the
  closed `arrow-big-*` shapes.
- Text and math marks.
- Charts drawn on axes.
- Icons whose body is clipped to make room for a badge, such as `user-round-check`, the
  `file-*-corner` family, and `calendar-plus`.
- Busy multi-part icons whose detail does not survive filling.
- Icons whose meaning depends on being empty, such as battery levels.

A filled drawing is optional; an icon without one is simply outline-only in both shapes, and its
component accepts only `variant="outline"` ([api.md](api.md#one-component-per-concept)).

## Adding a filled drawing

1. Add the icon's name to [config/filled.ts](../config/filled.ts) under its category, with an empty
   recipe.
2. Run `bun run derive:filled`, then `bun run derive:sharp` for the sharp filled drawing.
3. Run `bun run generate`, then `bun run playground`, and review the filled drawing beside the
   outline at 16, 24, and 48 px (the custom size reaches 48), in both shapes: bodies solid, details
   cut cleanly, crossing lines clear, nothing lost that the outline relies on.
4. Only if inference chose a wrong role, add a `roles` override for that element and repeat from
   step 2. If no recipe gives a clean result, leave the icon out.
5. Commit the recipe, both filled SVGs, and the generated files together.

Adding a filled drawing is a minor release; removing one is major, because `variant="filled"` stops
compiling for that icon ([api.md](api.md#versioning)). Changing the derivation code can change many
drawings at once, in both shapes: run `derive:filled` and `derive:sharp`, and review every drawing
in the diff.
